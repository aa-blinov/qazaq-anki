# Sources — реестр данных и происхождение словаря

Этот файл — центральный реестр источников, на которые ссылаются карточки
через поле `source`. Сами JSON в `decks/a1.json` … `c1.json` остаются
компактными: в них только короткий тег + URL.

## Где живут данные

```
src/data/
├── decks.json              ← список 5 уровней (id, name, tier, topics, cardCount)
├── decks/
│   ├── a1.json             ← { level, topicCount, topics: { slug: Card[] } }
│   ├── a2.json
│   ├── b1.json
│   ├── b2.json
│   └── c1.json
├── SOURCES.md              ← этот файл
├── decks.ts                ← тип Card, lazy-loader `loadLevel()`
└── decks.test.ts           ← интеграционные тесты
```

- **`decks.json`** — манифест, обновляется скриптом. `cardCount` —
  актуальное число карточек после дедупликации.
- **`decks/<level>.json`** — фактические данные. Файл лениво
  импортируется при первом заходе на уровень (Vite дробит bundle
  по уровням — A1: 32 КБ gz, C1: 38 КБ gz, B1: 107 КБ gz).
- **`SOURCES.md`** — этот файл. Единственный источник правды о
  лицензиях и атрибуции.
- **`decks.ts`** — `Card` тип, `loadLevel(id)` (async, кешируется),
  `getCategoriesByLevel`, `getCardCount`, `groupCardsByTopic`.

### Серверные данные

Официальные карточки (JSON выше) — это **bundled starter set**, общий
для всех пользователей. Пользовательские карточки (добавленные через
форму «+») живут **отдельно** на сервере в таблице `user_cards`:

```
server/data/qazaq.sqlite   ← SQLite (sql.js)
```

| Таблица         | Назначение                                                |
| --------------- | --------------------------------------------------------- |
| `users`         | id, username, displayName, passwordHash, **preferences**  |
| `sessions`      | token, userId, lastSeenAt                                 |
| `progress`      | (userId, cardId, direction) → SM-2 state JSON             |
| `review_log`    | append-only история оценок (для графика активности)       |
| `user_cards`    | приватные карточки пользователя (level, kazakh, …)        |
| `schema_meta`   | версия схемы (v0→v1→v2→v3)                                |

Схема версионируется через миграции в `server/db.js`. Сейчас
`SCHEMA_VERSION = 3`. Каждая миграция идемпотентна: можно вызывать
на каждом старте.

### Дедупликация и версионность

`scripts/unify-topics.mjs` приводит все 5 файлов к единой
таксономии и удаляет **кросс-уровневые дубли** по ключу
`(kazakh, translationRu).toLowerCase()`. Правило: «если слово
встречается в нескольких уровнях, оставляем в самом младшем»
(«танысу» = знакомство — слово уровня A1, в A2 оно дубль).

Скрипт переписывает ID-шники (`a1-0001`, `a1-0002`, …) при
каждом запуске — после дедупа они становятся компактнее.

## Структура карточки

```ts
interface Card {
  id: string;            // 'a1-0001', стабильный
  level: 'A1' | 'A2' | 'B1' | 'B2' | 'C1';
  category: string;      // slug темы (см. Таксономия ниже)
  kazakh: string;        // казахское слово/фраза
  transliteration: string; // латиница (отображается ТОЛЬКО под казахским)
  translation: string;   // EN (для данных, не для UI)
  translationRu: string;// RU (основной перевод в UI)
  example: string;       // пример (пока пустой — KazParC ниже)
  deck: 'cefr' | 'user';
  source?: string;       // 'kazcorpus-lexmin-v1'
  sourceUrl?: string;   // прямая ссылка на PDF-страницу + якорь на слово
  license?: string;      // SPDX: 'CC-BY-4.0'
  attribution?: string;  // 'Ахмет Байтұрсынұлы атындағы Тіл білімі…'
}
```

`source`, `sourceUrl`, `license`, `attribution` бэкфилятся на лету
в `loadLevel()` (см. `src/data/decks.ts`) — в JSON их нет, чтобы
файлы оставались компактными.

### Per-card источник

Каждая карточка из `kazcorpus-lexmin-v1` имеет **уникальный**
`sourceUrl`:

```
https://qazcorpus.kz/_oqu-ishorpus/Sauattik/pdf/Лексикалық_минимум_A1.pdf#танысу
```

Якорь `#танысу` — это slug самого слова. PDF-просмотрщики
(Firefox/Chrome built-in, Adobe) поддерживают anchor scroll, так
что ссылка открывает PDF на нужном слове.

## Таксономия тем

Карточки группируются по 34 каноническим темам. Каждая тема — это
`slug` (стабильный ключ) + пара `{ ru, kz }` для отображения в
формате **«RU / KZ»** (требование проекта).

```
A1:  Семья, Дом, Работа, Еда, Досуг, Погода, Одежда, Здоровье, Праздники, Хобби ...
A2:  Семья, Здания, Досуг, Время, Имена, Внешность, Страна, Растения, Услуги, Биография, Документы
B1:  Работа, Еда, Одежда, Общение, СМИ, Образ жизни, Путешествия, Мир, Образование, Быт ...
B2:  Желание, Информация, Отрицание
C1:  Страны, Сезон, Отходы, Цветы, Принадлежности, Антипатия, Продолжение,
     Еда, Питание, Оценка, Намерение, Прилагательные, Местоимения, Группы
```

Канонический список зафиксирован в
[`scripts/unify-topics.mjs`](../../scripts/unify-topics.mjs) и
выводится в [`src/i18n/topics.ts`](../i18n/topics.ts). UI получает
лейблы через `useLang().tTopic(slug)` → возвращает «RU / KZ».

### Правила

- **Одна тема — один slug** (например, «Personalities» из B1
  схлопнулась в `work`, «МАМАНДЫҚТЫҢ БӘРІ ЖАҚСЫ» — в `work`).
- **Кросс-уровневые дубли** удаляются. Слово «танысу» в A1
  (Greetings) и в A2 (Family) — оставляем в A1, в A2 дропаем.
- **Слово в двух темах одного уровня** — оставляем в той, в
  которой оно встретилось первым при парсинге (стабильный порядок
  благодаря `Map` в скрипте).
- **Парсинг секций** определяется старым названием (англ. или
  смешанный кириллический заголовок в PDF). Алиасы — в `TOPICS`
  массиве скрипта.

## Источники

### `kazcorpus-lexmin-v1` — основной (3 996 карточек)

- **URL**: <https://qazcorpus.kz/_oqu-ishorpus/Sauattik/pdf/Лексикалық_минимум_A1.pdf>
  (для A2/B1/B2/C1 — замените `A1` на нужный уровень)
- **Лицензия**: CC-BY-4.0
- **Attribution**: «Ахмет Байтұрсынұлы атындағы Тіл білімі институты.
  Лексикалық минимумдер A1–C1. Астана, 2017–2018. ISBN 978-601-7311-32-2.»
- **Что внутри**: 5 755 уникальных казахских слов с транслитерацией,
  переводом на русский и английский, по темам. Официальный
  лексический минимум Института языкознания им. А. Байтұрсынова,
  изданный по заказу Комитета по развитию языков Министерства
  культуры и спорта РК в рамках Государственной программы
  развития языков 2011-2020.
- **Per-card `sourceUrl`**: PDF-страница + якорь на слово.
  PDF-просмотрщик открывает страницу со скроллом к нужному слову.
- **Структура**:
  - A1 — 720 слов, 12 тем в источнике (после дедупа 712)
  - A2 — 1 338 слов, 11 тем (после дедупа 693 — большая часть дублей с A1)
  - B1 — 2 243 слов, 12 тем (после дедупа 1 559)
  - B2 — 548 слов, 3 темы (parser-ограничение)
  - C1 — 906 слов, 11 тем (после дедупа 583)
- **Как обновить**: `node scripts/build-lexmin.mjs /path/to/lexmin/`
  (см. [Регенерация данных](#регенерация-данных) ниже)

### `anki-qazaq-curated-v1` (deprecated)

Использовался для 1 272 hand-curated карточек до подключения
официального `kazcorpus-lexmin-v1`. Полностью заменён — у qazcorpus
есть per-card `sourceUrl` с проверяемой атрибуцией, что у
`curated-v1` отсутствовало. JSON'ы лежат в `src/data/curated/`
для истории.

### Пользовательские карточки (`deck: 'user'`)

Создаются через UI («+» на странице «Все слова»). Поля
`source` / `sourceUrl` / `license` / `attribution` заполняются
пользователем. По умолчанию пустые. Хранятся в `user_cards`
на сервере, привязаны к `ownerUserId`. Удаляются кнопкой «×»
на Browse-странице.

## Как добавить новый источник

1. **Придумай короткий тег** в `lower-kebab-case`, например
   `til-balalag` или `kazparc-sentences`.
2. **Добавь запись** в этот файл (URL, лицензия, attribution,
   что внутри, как обновить).
3. **Используй тег** в `source` нужной карточки.
4. **Если лицензия не CC-BY** — добавь обязательный `attribution`
   на каждую карточку (для CC-BY достаточно одного `attribution`
   на весь источник).
5. **Проверь тестами**: `decks.test.ts` валидирует, что у каждой
   карточки есть `source` и `license`.

## Регенерация данных

### Из PDF-источника (kazcorpus)

```bash
# 1. Скачай 5 PDF-ов с qazcorpus.kz в /tmp/lexmin/
#    (на странице https://qazcorpus.kz/_oqu-ishorpus/Sauattik/)
mkdir -p /tmp/lexmin
# 2. Положи туда файлы: lexmin_A1.pdf, lexmin_A2.pdf, …

# 3. Запусти парсер — генерирует src/data/decks/{a1..c1}.json
node scripts/build-lexmin.mjs /tmp/lexmin

# 4. Унифицируй темы + удали кросс-уровневые дубли
node scripts/unify-topics.mjs

# 5. Запусти тесты
npm test
```

`build-lexmin.mjs` использует `pdfjs-dist` для извлечения текста.
Парсит ToC по римским/кириллическим цифрам в A1/A2/B1, для
B2/C1 — по per-page header detection. Y-coordinate grouping
объединяет строки в одну запись. Дедуп по `(kk + ru)`.

`unify-topics.mjs` — переписывает `decks/*.json` с единой
таксономией (slug → `{ ru, kz }`) и кросс-уровневой дедупликацией.
Идемпотентен: повторный запуск даёт тот же результат.

### Из Wiktionary (опционально, через kaikki.org)

```bash
# См. https://kaikki.org/dictionary/Kazakh/
# Скачай JSONL, конвертируй в формат Card (можно через скрипт-конвертер).
# Добавь в `decks/a1.json` с `source: 'wiktionary-kk'`.
```

## Как цитировать

При использовании словаря в своих материалах указывай:

> Qazaq learning project на основе лексического минимума
> Института языкознания им. А. Байтұрсынова (CC-BY-4.0) —
> <https://qazcorpus.kz/_oqu-ishorpus/Sauattik/>

В UI: ссылка «источник» на обороте карточки ведёт на конкретное
PDF + якорь на слово. License `CC-BY-4.0` показывается рядом,
если он нестандартный.
