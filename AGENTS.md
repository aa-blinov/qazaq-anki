# AGENTS.md — agent context for `qazaq-anki`

A self-hosted spaced-repetition flashcard app for learning Kazakh. A React SPA talks to an Express API over a SQLite file, and the vocabulary, the pronunciation clips and the topic taxonomy are all committed to the repository.

This file is what you need to work on the project without reading all of it.

## Run / build / test

```bash
npm ci              # install
npm run server      # the API on :3001, restarting on change
npm run dev         # the front end on :5173, proxying /api to :3001
npm test            # Vitest over src/**/*.test.ts, jsdom, 11 files
npm run e2e         # Playwright, 18 spec files, its own API on :3011
npm run build       # tsc -b, vite build, then dist/404.html for the Pages fallback
npm run build:quick # the Vite build alone, no typecheck
npm run preview     # serve dist/
npm run deploy      # publish landing/ to the gh-pages branch
npm run deploy:app  # build for /qazaq-anki/ and publish dist/
```

Node 22. The API is plain ESM with no build step; the front end is TypeScript and React 19 built by Vite 6.

```bash
docker compose up -d --build                          # api, web, tts, backups on :8080
docker compose --profile prod up -d --build            # the same, behind Caddy on :80/:443
```

`docker compose up` fails on the backup service until `secrets/admin_token.txt`
exists, because Compose mounts the secret as a bind mount and refuses to
create the container when the file is missing. The API needs the same value in
`ADMIN_TOKEN`, or the admin routes stay closed and the backup job cannot reach
the checkpoint endpoint.

## Traps

- **The live API is at the repository root, not in `server/`.** `server/server.js`
  and `server/db.js` are older copies that nothing runs. `npm run server`,
  `npm start`, the CI smoke job and `playwright.config.ts` all start the root
  `server.js`, and `server/Dockerfile` builds with the repository root as the
  context and copies `/app/server.js` from there. Editing `server/server.js`
  changes nothing that runs. The root copy has the WAL checkpoint, the admin
  routes, the `health_writes` table and the configurable rate limits; the copy
  in `server/` has none of them.
- **The API is required. The front end on its own cannot register anyone.**
  Accounts, progress, the review log, the preferences blob and the statistics
  are all server-side, and `ProgressContext` reads progress from
  `/api/progress` on load. A front end served without an API is a page where
  nothing works, and `landing/` says so rather than pretending otherwise.
- **`docs/concepts.md` is out of date.** It describes a 1,272-card deck, a
  "Common" pseudo-level and progress kept in `localStorage` under
  `aq:progress:${userId}`. None of that is true of the current code: the deck
  is 3,996 cards across five CEFR levels, there is no "Common" level, and
  progress is server-side. The `level` versus `category` distinction it
  argues for is still real and worth reading; the numbers in it are not.
- **The card data is generated.** `src/data/decks/{a1..c1}.json` is the output
  of `scripts/build-lexmin.mjs` followed by `scripts/unify-topics.mjs`. Hand
  edits are overwritten by the next run, and `src/data/decks.test.ts` pins the
  card counts, the id format, the topic slugs and the uniqueness of the ids.
  A card added by hand also needs its `cardCount` in `src/data/decks.json`
  bumped to match.
- **The audio filename is a hash of the word.** `src/lib/tts.ts` re-implements
  SHA-1 by hand and takes the first 16 hex characters, and it must agree with
  `word_hash` in `scripts/generate_tts.py`. Change one and you change the
  other, or every clip URL breaks and the speak buttons go quiet. The URL
  therefore ignores case and punctuation, and the same word always maps to the
  same file.
- **The interface is Russian-only.** `setLang` in
  `src/contexts/LanguageContext.tsx` is a no-op and no control calls it. The
  `en` dictionary exists so a missing key falls back instead of blanking the
  interface, and `src/i18n/i18n.test.ts` checks that every Russian key has an
  English twin, that no value is empty and that every plural base carries the
  one, few and many forms.
- **The browser holds four keys and no more.** `aq:token`, `aq:theme`,
  `aq:fontSize`, `aq:ttsSpeed`. The onboarding flags are server-side columns
  on `users`, not localStorage. Progress does not appear in the browser at
  all.
- **The token travels in the `Authorization` header.** Not in a cookie, and
  not in the URL. There is no CSRF surface to defend because there is no
  cookie.
- **The admin routes only exist when `ADMIN_TOKEN` is set.** Without it,
  `/api/admin/checkpoint` and `/api/admin/backup-now` answer 404 and the
  backup container restarts in a loop, saying why in its log. The backup
  script calls the checkpoint first, so the snapshot is a coherent file rather
  than a main file with a dirty write-ahead log beside it.
- **The e2e suite never touches your dev server.** It starts `node server.js`
  on port 3011 with `DB_PATH=server/data/test.sqlite` and a Vite on port 5174
  proxying to it, wipes the test database in the global setup and removes it
  in the teardown. It also raises `RATE_LIMIT_REGISTER` and
  `RATE_LIMIT_LOGIN` to 1000, because a suite that registers a fresh user in
  every spec would trip the production limiter around the sixth one. The
  production defaults stay at 5 and 10.
- **The Vite base path is baked into the build.** `vite.config.ts` reads
  `VITE_BASE` and falls back to `/qazaq-anki/` for a production build.
  `npm run deploy:app` sets it, `npm run build` does not. A bundle built with
  the wrong base loads its assets from a path that does not exist, and the
  failure looks like a blank page rather than a configuration error.
- **`npm run deploy` publishes the landing page, not the app.** GitHub Pages
  serves `landing/`. The app needs the API, so a Pages deploy of `dist/` is a
  site where registration silently does not work. The landing page says this
  in both languages.
- **The Docker web image builds the bundle inside the image.**
  `docker compose build qazaq-web` is the only command needed; the base path
  comes from the build argument `VITE_BASE`, not from a `dist/` on the host.
- **The database path is relative to the working directory.** `db.js` resolves
  `DB_PATH` and falls back to `<cwd>/data/qazaq.sqlite`, so a bare
  `npm run server` writes into `data/` at the repository root. The container
  image sets `DB_PATH=/data/qazaq.sqlite` for the named volume, and the
  Dockerfile says the variable is required in production so that a stale image
  cannot write into a fresh empty file; the code itself falls back rather than
  refusing to start.

## Style / safety rails

- **The interface is Russian.** New strings go into `src/i18n/ru.ts`, with an
  English twin in `src/i18n/en.ts`. Kazakh appears only where the learner is
  studying it.
- **The vocabulary is never edited by hand.** Change the source and
  regenerate, or change the taxonomy in `scripts/unify-topics.mjs` and
  regenerate.
- **No third-party requests.** The fonts are self-hosted so that loading a
  page does not disclose the learner's IP to a CDN. A telemetry call, an
  analytics script or a font from a CDN breaks that in a way no test catches.
- **The API keeps four runtime dependencies** (`bcryptjs`, `cors`, `express`,
  `sql.js`) plus `adm-zip` for the Anki import. The security headers are
  written by hand in `server.js` and in `deploy/nginx.conf` rather than
  pulled in from a framework, for the same reason.
- **Every SQL statement is prepared.** No string concatenation into
  `db.exec()`, apart from the fixed migration strings in `db.js`.
- **Comments explain why, never what.** The comments in this repository are
  unusually good on this point and carry the reasoning a future change would
  otherwise have to rediscover.
- **No emoji, anywhere.**
