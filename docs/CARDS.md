# CARDS — словарный состав и таксономия

Документ для разработчиков: где живут данные, как они
собираются, как устроена таксономия тем, как обновлять.

Аудитория: фронтендеры, которые добавляют/чинят карточки,
и контрибьюторы, которые подключают новые источники.

> Юридическая сторона (лицензии, ISBN, ISBN издательства) — в
> [`src/data/SOURCES.md`](../src/data/SOURCES.md). Этот файл —
> про **архитектуру и процессы**.

---

## 1. Где живут данные

| Путь                                   | Что                                                |
| -------------------------------------- | -------------------------------------------------- |
| `src/data/decks.json`                  | манифест: 5 уровней, их tier, темы, cardCount      |
| `src/data/decks/{a1..c1}.json`         | собственно карточки, лениво импортируются по уровню |
| `src/data/decks.ts`                    | `Card` тип + `loadLevel(id)` + `groupCardsByTopic` |
| `src/data/decks.test.ts`               | интеграционные тесты структуры                     |
| `src/i18n/topics.ts`                   | slug → `{ ru, kz }` для UI                         |
| `scripts/build-lexmin.mjs`             | PDF-парсер для qazcorpus-lexmin-v1                 |
| `scripts/unify-topics.mjs`             | маппинг тем + дедуп + перенумерация ID             |
| `src/data/SOURCES.md`                  | юридическая сторона (лицензии, attribution)        |

```
[ PDF с qazcorpus.kz ]
        │
        ▼
[ scripts/build-lexmin.mjs ]   ← первичный парсер
        │
        ▼
[ src/data/decks/{a1..c1}.json ]   ← сырой выход (с кириллическими заголовками тем)
        │
        ▼
[ scripts/unify-topics.mjs ]   ← маппинг тем + дедуп + перенумерация
        │
        ▼
[ src/data/decks/{a1..c1}.json ]   ← финальный вид (slug тем, 4-значные ID, без кросс-дублей)
        │
        ▼
[ src/i18n/topics.ts ]        ← сгенерированный таксон-каталог
        │
        ▼
[ src/data/decks.ts::loadLevel ]  ← обогащает source/license/attribution
        │
        ▼
[ UI: Study, Browse, Stats ]
```

`decks/*.json` **никогда не редактируются вручную** — это либо
выход парсера, либо выход unify-скрипта. Если нужна правка,
правь исходник (PDF) и перегенерируй, либо добавь алиас в
`scripts/unify-topics.mjs::TOPICS`.

## 2. Структура карточки

```ts
interface Card {
  id: string;            // 'a1-0001' — стабильный в пределах уровня
  level: 'A1' | 'A2' | 'B1' | 'B2' | 'C1';
  category: string;      // slug из TOPICS (см. § 3)
  kazakh: string;        // казахское слово/фраза
  transliteration: string; // латиница — отображается ТОЛЬКО под казахским
  translation: string;   // EN (для данных, не для UI)
  translationRu: string;// RU (основной перевод в UI)
  example: string;       // пример (пока пустой)
  deck: 'cefr' | 'user';
  source?: string;       // 'kazcorpus-lexmin-v1' (бэкфилится в loadLevel)
  sourceUrl?: string;    // прямая ссылка на PDF + якорь на слово
  license?: string;      // SPDX: 'CC-BY-4.0'
  attribution?: string;  // 'Ахмет Байтұрсынұлы атындағы Тіл білімі…'
}
```

`source` / `sourceUrl` / `license` / `attribution` бэкфилятся на
лету в `loadLevel()` — в JSON их нет, чтобы файлы оставались
компактными. Если карточка уже содержит `sourceUrl` (например,
из kazcorpus-парсера), он сохраняется.

Список зафиксирован в
[`scripts/unify-topics.mjs`](../scripts/unify-topics.mjs) —
массив `TOPICS`. UI получает лейблы через
`useLang().tTopic(slug)` → возвращает «RU / KZ».

### Правила

1. **Одна тема — один slug.** Если в исходном PDF было
   «Personalities» (B1) и «МАМАНДЫҚТЫҢ БӘРІ ЖАҚСЫ» (B1) — оба
   мапятся в `work`. Алиасы перечислены в `TOPICS[].aliases`.
2. **Кросс-уровневые дубли удаляются.** «танысу» (знакомство)
   в A1 и A2 — оставляем в A1. Правило: **младший уровень
   выигрывает**, потому что базовые слова должны ассоциироваться
   с самым первым уровнем, на котором их вводят.
3. **Внутри-уровневые дубли** оставляются в той теме, где
   встретились первыми (стабильный порядок благодаря `Map`).
4. **Заголовки в кириллице** (B2/C1) — нормализуются fuzzy
   matcher'ом: убираем запятые, лишние пробелы, ищем по
   «collapsed» форме.

## 4. Источники (кратко)

Полная юридическая сторона — в `src/data/SOURCES.md`. Здесь —
только **где что брать и как подключить**.

### Активный: kazcorpus-lexmin-v1

5 755 уникальных слов из официального лексического минимума.
CC-BY-4.0, ISBN 978-601-7311-32-2.

Подключение: парсер лежит в `scripts/build-lexmin.mjs`.
Использует `pdfjs-dist` для извлечения текста, ToC по
римским/кириллическим цифрам (A1/A2/B1), per-page header
detection для B2/C1. Y-coordinate grouping объединяет
строки в одну запись.

### Депрекейтнутый: anki-qazaq-curated-v1

1 272 hand-curated карточек. Полностью заменён на kazcorpus.
JSON'ы в `src/data/curated/` для истории, в UI не попадают.

### Будущие

- **kazparc** — 371 902 параллельных предложения kk-en-ru-tr от
  IS2AI (CC-BY-4.0). Будет заполнять поле `example`.
- **wiktionary-kk** через kaikki.org (12 288 уникальных слов,
  CC-BY-SA-4.0).
- **tatoeba** — корпус предложений (CC-BY-2.0).

## 5. Регенерация данных

### Шаг 1: парсинг PDF

```bash
# 1. Скачай 5 PDF с qazcorpus.kz:
#    https://qazcorpus.kz/_oqu-ishorpus/Sauattik/
#    lexmin_A1.pdf, lexmin_A2.pdf, lexmin_B1.pdf, lexmin_B2.pdf, lexmin_C1.pdf
mkdir -p /tmp/lexmin
mv ~/Downloads/lexmin_*.pdf /tmp/lexmin/

# 2. Запусти парсер
node scripts/build-lexmin.mjs /tmp/lexmin
# → src/data/decks/{a1..c1}.json (сырые, с кириллическими заголовками тем)
```

Парсер **никогда не перезаписывает** файл, в котором 0 слов —
страховка от регрессии.

### Шаг 2: унификация + дедуп

```bash
# Применяет таксономию (slug → ru/kz) и удаляет кросс-уровневые дубли.
# Перенумеровывает ID (a1-0001, a1-0002, …).
# Регенерирует src/i18n/topics.ts.
node scripts/unify-topics.mjs
```

`unify-topics.mjs` идемпотентен — повторный запуск даёт тот же
результат. Если 0 карточек пережило дедуп, скрипт **откажется
писать** и оставит файлы как есть (страховка).

### Шаг 3: проверка тестами

```bash
npm test
# 83/83 должно проходить.
# topics.test.ts проверяет таксономию.
# decks.test.ts проверяет структуру (ID, slug в каноне, ≥100 карт/уровень, …)
```

### Шаг 4: визуальная проверка

```bash
npm run dev
# Зайди в /study/a1, /browse, /stats — темы должны быть в формате «RU / KZ».
```

## 6. Как добавить новый источник (пошагово)

См. также «Как добавить новый источник» в `SOURCES.md`.

1. **Положи исходник** в `src/data/raw/<source-tag>/` (если
   PDF) или подключи API (если онлайн-источник).
2. **Напиши парсер** в `scripts/build-<source-tag>.mjs`. Он
   должен:
   - выдать `Card[]` с заполненными `source`, `sourceUrl`, `license`;
   - не падать на 0 результатах (логировать, но не очищать
     существующий JSON);
   - идемпотентно (повторный запуск = тот же результат).
3. **Добавь алиасы** в `scripts/unify-topics.mjs::TOPICS` — для
   каждой новой темы укажи slug + ru/kz + список алиасов
   из исходника.
4. **Добавь запись** в `src/data/SOURCES.md` (URL, лицензия,
   attribution, как обновить).
5. **Допиши тест** в `decks.test.ts` — что каждая карточка
   имеет `source` (если у тебя не bundled).
6. **Запусти всё**: `npm test && npm run e2e`.

## 7. Известные ограничения

- **B2 имеет 3 темы** (parser-ограничение). Заголовки секций в
  PDF разнесены по строкам, header detector не схлопывает.
  TODO: улучшить `isHeaderRow` regex / сделать Y-aware merge.
- **C1 тоже можно больше тем** — те же причины.
- **`example` пуст** у всех карточек. Будет заполнен из
  KazParC, когда подключим.
- **Кросс-уровневые дубли** удалены по правилу «младший
  выигрывает». Тест `cross-level sanity` ослаблен до
  «нет нулевого словаря» — это документированное поведение,
  не баг.
- **Стартовая колода уникальна по (kk, ru)**, не по kk
  одному. Например, «мен» в значении «я» и «мен» в значении
  «мука» — две карточки. Дедип только строгий.
- **Кириллические заголовки в PDF (B2/C1)** были в формате
  «ҚАЗАҚША / RUSSIAN / ENGLISH» — парсер склеивает всё, что
  в верхнем регистре, и пропускает. Если в B2 PDF формат
  изменится — поправить `isHeaderRow`.
